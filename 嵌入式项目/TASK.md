| 当前状态      | 触发事件                 | 下一状态      |
| --------- | -------------------- | --------- |
| Ready     | 被调度器选中               | Running   |
| Running   | 调用 `vTaskDelay()`    | Blocked   |
| Running   | 等队列/信号量/事件           | Blocked   |
| Blocked   | 时间到 / 事件到            | Ready     |
| Running   | 被更高优先级任务抢占           | Ready     |
| Running   | 被挂起 `vTaskSuspend()` | Suspended |
| Suspended | 被恢复 `vTaskResume()`  | Ready     |
| Running   | 被删除 `vTaskDelete()`  | Deleted   |

Blocked -> Ready -> Running

```c
void TaskA(void *argument)
{
    for (;;)
    {
        printf("A\r\n");
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void TaskB(void *argument)
{
    for (;;)
    {
        printf("B\r\n");
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

xTaskCreate(TaskA, "TaskA", 128, NULL, 1, NULL);
xTaskCreate(TaskB, "TaskB", 128, NULL, 2, NULL);
```

- TaskA：Blocked
- TaskB：Blocked

系统会运行 **Idle Task**

# 练习5：高优先级任务被唤醒时会发生什么

先设定场景：

- `TaskA` 优先级 1，当前正在 Running
- `TaskB` 优先级 3，之前一直因为等待消息而 Blocked
- 现在消息到了，`TaskB` 从 Blocked 变成 Ready

## 问题

这时谁运行？`TaskA` 状态会变什么？

---

## 标准答案

- `TaskB` 会开始运行
- `TaskA` 从 Running 变成 Ready


# 1. 任务栈是什么

** 任务栈（Task Stack）** 是每个任务独立拥有的一段内存空间，用于：

- 保存函数调用的**局部变量**
- 保存函数调用**返回地址**
- 任务切换时保存**CPU 寄存器现场**

每个任务都必须有自己的栈，互不干扰，保证任务独立运行。

---

# 2. TCB 是什么

**TCB = Task Control Block（任务控制块）**

是一个**结构体**，保存任务的所有管理信息：

- 任务优先级
- 任务状态（就绪 / 阻塞 / 挂起）
- 栈顶指针
- 延时、事件、队列等阻塞信息

RTOS 靠 TCB 管理所有任务。

---

# 3. 动态创建任务为什么会占 heap

`xTaskCreate()` 动态创建时，RTOS 会从堆里**自动申请两段内存**：

1. **TCB 结构体**
2. **任务栈空间**

所以动态任务一定会用 heap。

如果用静态创建 `xTaskCreateStatic()`，则由用户提供内存，不占 heap。

---

# 4. heap_1 ~ heap_5 的整体区别

FreeRTOS 提供 5 种堆管理方案，核心差异：**是否支持释放、是否支持合并、是否支持多块内存**

| 方案         | 能否释放           | 能否合并        | 多块 RAM 支持     | 特点           |
| ---------- | -------------- | ----------- | ------------- | ------------ |
| **heap_1** | ❌ 不能释放         | ❌           | ❌             | 只分配不释放，最简单安全 |
| **heap_2** | ✅ 可释放          | ❌ 不合并       | ❌             | 会产生严重碎片      |
| **heap_3** | 封装 malloc/free | -           | -             | 依赖编译器库，线程不安全 |
| **heap_4** | ✅ 可释放          | ✅ 自动合并相邻空闲块 | ❌             | 平衡易用性、效率、抗碎片 |
| **heap_5** | ✅ 可释放          | ✅ 自动合并      | ✅ 支持多段非连续 RAM | 功能最强，适合大内存系统 |
# 5. heap_4 为什么最常用

heap_4 是**综合最优**：

1. 支持**分配 + 释放**
2. 支持**空闲块自动合并**，大大减少碎片
3. 实现简单、开销小
4. 不依赖编译器库，可重入、线程安全
5. 绝大多数 MCU 单块 RAM 足够用

因此几乎所有工程默认用 heap_4。

---

# 6. heap_4 是怎么切块、释放、合并的

## 分配（切块）

1. 用**链表**管理所有空闲块
2. 遍历找到**第一个足够大**的空闲块（首次适应）
3. 如果块比需求大，**切成两块**
    
    - 一块返回给用户
    - 剩下的仍留在空闲链表
    
4. 块头部保存大小、是否空闲等信息

## 释放

1. 将块标记为空闲
2. **检查前后相邻块是否也空闲**
3. 若相邻块空闲，则**合并成一个更大块**
4. 重新插入链表

## 合并

heap_4 核心就是**释放时自动合并相邻空闲块**，这是它抗碎片的关键。

---

# 7. 为什么会出现内存碎片

即使总空闲很大，也会出现很多**小而不连续**的空闲块。

原因：

- 多次**alloc + free** 大小不一
- 空闲块被已分配块隔开
- heap_2 这种**不合并**的策略会快速碎片
- heap_4 虽合并，但仍无法合并**不相邻**块

最终：**总空闲够，但没有连续大块**。

---

# 8. 为什么总空闲够也可能申请失败

一句话：

**总空闲大小 ≥ 申请大小，但没有一块连续空闲块 ≥ 申请大小。**

例子：

- 总空闲：1000 字节
- 但分成 3 块：200 + 300 + 500
- 申请 600 字节 → 失败

这就是**内存碎片**导致的典型问题。

---

# 简短总结

- **任务栈**：任务运行的临时空间
- **TCB**：任务管理结构体
- **动态任务**：需要从堆申请 TCB + 栈
- **heap_4**：最常用，因为支持分配、释放、自动合并、抗碎片
- **碎片**：空闲内存不连续
- **总空闲够仍失败**：无足够大连续块
