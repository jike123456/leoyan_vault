# 9、控制任务的出发条件什么？是周期运行还是事件驱动？

接第 8 题，**ControlTask 不是单纯周期运行，也不是单纯事件驱动，而是“两阶段机制”**：

```text
空闲时：事件驱动
运行时：周期运行
```

文档里写得比较明确：ControlTask 采用两级模式 `CTRL_IDLE / CTRL_RUN`，只有确实存在运动指令时才执行闭环控制；没有指令或车辆停稳时，会退出控制循环并阻塞等待。页面顶部也说明控制任务在运行阶段按固定周期执行，周期是 **10 ms 一次，也就是 100 Hz**。

### 1. 空闲模式：事件驱动

刚启动或者没有有效运动指令时，ControlTask 处于 `CTRL_IDLE`。

这时它不会一直循环算 PID，而是：

```c
xTaskNotifyWait(..., portMAX_DELAY);
```

也就是**无限期阻塞等待通知**。

触发它醒来的条件是：

```text
CommTask 解析到新的有效速度指令
  ↓
发送 NOTIF_NEW_CMD 通知
  ↓
ControlTask 被唤醒
```

所以在空闲状态下，它是**事件驱动**的。

### 2. 运行模式：周期运行

当 ControlTask 收到 `NEW_CMD` 后，会读取最新速度指令：

```c
ref_cmd = Comm_GetLatestCmdVel();
```

然后切换到：

```c
CTRL_RUN
```

进入运行模式后，它就按固定周期执行闭环控制：

```text
每 10 ms 执行一次
也就是 100 Hz
```

每个周期里大致做这些事：

```text
检查是否有新命令
  ↓
判断指令是否超时
  ↓
运动学逆解，算左右轮目标速度
  ↓
PID 计算
  ↓
输出 PWM 到电机
```

### 3. 运行中也会检查事件

在 `CTRL_RUN` 里，ControlTask 不会再用 `portMAX_DELAY` 阻塞，而是用非阻塞方式检查有没有新命令：

```c
xTaskNotifyWait(..., timeout = 0);
```

意思是：

```text
有新命令就立即更新 ref_cmd
没有新命令就继续用上一条有效指令控制
```

所以运行阶段的主节奏是**周期控制**，但也会顺便检查事件通知。

### 4. 什么时候退出运行？

如果长时间没有新的有效指令，或者判断当前指令超时，ControlTask 会认为控制命令失效：

```text
指令超时
  ↓
ref_cmd 无效
  ↓
PWM 输出清零
  ↓
PID 状态复位
  ↓
回到 CTRL_IDLE
```

然后再次进入阻塞等待状态。

总结一句话：

**ControlTask 在没有指令时是事件驱动，靠 `TaskNotify` 唤醒；收到有效指令后进入 `CTRL_RUN`，按 10 ms 周期运行 PID 闭环控制；如果指令超时或无效，再回到 `CTRL_IDLE` 阻塞等待。**

# 10、控制任务中两级模式的切换条件是什么？

控制任务的两级模式是：

```text
CTRL_IDLE  空闲/阻塞等待模式
CTRL_RUN   10ms周期闭环控制模式
```

切换条件可以这样理解：

```text
CTRL_IDLE
  ↓ 收到 CommTask 的 NOTIF_NEW_CMD，并且能读取到有效速度指令
CTRL_RUN
  ↓ 指令超时 / 指令无效 / 需要刹停并已进入安全停止状态
CTRL_IDLE
```

### 1. `CTRL_IDLE -> CTRL_RUN`

在 `CTRL_IDLE` 模式下，ControlTask 认为当前**没有有效运动指令**，所以会先做安全处理：

```text
PWM = 0
PID 状态复位
电机保持停止
```

然后阻塞等待新指令：

```c
xTaskNotifyWait(..., portMAX_DELAY);
```

当 CommTask 解析到有效速度帧后，会发送任务通知 `NOTIF_NEW_CMD`。ControlTask 被唤醒后，检查通知值，如果包含新指令标志，就读取最新速度命令：

```c
if (notify_val & NOTIF_NEW_CMD) {
    ref_cmd = Comm_GetLatestCmdVel();
    last_cmd_ms = now_ms();
    mode = CTRL_RUN;
}
```

所以 **从 IDLE 切到 RUN 的条件**是：

```text
收到 NOTIF_NEW_CMD 通知
并且读取到有效的 CmdVel 速度指令
```

文档第 1 页 3.5.1 和 3.5.2 里说明，空闲模式下 ControlTask 会用 `xTaskNotifyWait(..., portMAX_DELAY)` 阻塞等待，收到 CommTask 的新速度指令通知后，读取最新指令并切换到 `CTRL_RUN`。

### 2. `CTRL_RUN -> CTRL_IDLE`

进入 `CTRL_RUN` 后，ControlTask 按 **10ms 周期**运行闭环控制：

```text
读取/更新控制指令
↓
运动学逆解
↓
PID 计算 PWM
↓
输出到电机
↓
判断指令是否仍然有效
```

在运行过程中，它会持续检查有没有新命令。如果有新命令，就更新目标速度；如果长时间没有新命令，就认为上层控制失效或通信中断。

所以 **从 RUN 切回 IDLE 的条件**是：

```text
指令超时
或当前没有有效指令
或车辆已经完成刹停并处于稳定停止状态
```

通常逻辑是：

```c
if (now_ms() - last_cmd_ms > CMD_TIMEOUT_MS) {
    ref_cmd.valid = false;
    ref_cmd.vx_mmps = 0;
    ref_cmd.wz_mradps = 0;

    pwm_hw_apply(0, 0);
    pid_reset();

    mode = CTRL_IDLE;
}
```

更完整地说，RUN 模式下不是“没收到新命令就马上停”，而是：

```text
短时间没有新命令：继续使用上一条有效指令
超过超时时间：认为指令失效
指令失效后：目标速度置零，进入刹车/停机流程
停稳后：切回 CTRL_IDLE，重新阻塞等待新指令
```

### 3. 一句话总结

**`CTRL_IDLE -> CTRL_RUN` 的条件是收到 CommTask 的有效新速度指令；`CTRL_RUN -> CTRL_IDLE` 的条件是指令超时、指令无效或车辆已安全停稳。**

也就是：

```text
有有效指令：进入 RUN，10ms 周期闭环控制
无有效指令：回到 IDLE，PWM 清零，PID 复位，阻塞等待
```
