# 9、控制任务的出发条件什么？是周期运行还是事件驱动？

接第 8 题，**ControlTask 不是单纯周期运行，也不是单纯事件驱动，而是“两阶段机制”**：

```text
空闲时：事件驱动
运行时：周期运行
```

文档里写得比较明确：ControlTask 采用两级模式 `CTRL_IDLE / CTRL_RUN`，只有确实存在运动指令时才执行闭环控制；没有指令或车辆停稳时，会退出控制循环并阻塞等待。页面顶部也说明控制任务在运行阶段按固定周期执行，周期是 **10 ms 一次，也就是 100 Hz**。

### 1. 空闲模式：事件驱动

刚启动或者没有有效运动指令时，ControlTask 处于 `CTRL_IDLE`。

这时它不会一直循环算 PID，而是：

```c
xTaskNotifyWait(..., portMAX_DELAY);
```

也就是**无限期阻塞等待通知**。

触发它醒来的条件是：

```text
CommTask 解析到新的有效速度指令
  ↓
发送 NOTIF_NEW_CMD 通知
  ↓
ControlTask 被唤醒
```

所以在空闲状态下，它是**事件驱动**的。

### 2. 运行模式：周期运行

当 ControlTask 收到 `NEW_CMD` 后，会读取最新速度指令：

```c
ref_cmd = Comm_GetLatestCmdVel();
```

然后切换到：

```c
CTRL_RUN
```

进入运行模式后，它就按固定周期执行闭环控制：

```text
每 10 ms 执行一次
也就是 100 Hz
```

每个周期里大致做这些事：

```text
检查是否有新命令
  ↓
判断指令是否超时
  ↓
运动学逆解，算左右轮目标速度
  ↓
PID 计算
  ↓
输出 PWM 到电机
```

### 3. 运行中也会检查事件

在 `CTRL_RUN` 里，ControlTask 不会再用 `portMAX_DELAY` 阻塞，而是用非阻塞方式检查有没有新命令：

```c
xTaskNotifyWait(..., timeout = 0);
```

意思是：

```text
有新命令就立即更新 ref_cmd
没有新命令就继续用上一条有效指令控制
```

所以运行阶段的主节奏是**周期控制**，但也会顺便检查事件通知。

### 4. 什么时候退出运行？

如果长时间没有新的有效指令，或者判断当前指令超时，ControlTask 会认为控制命令失效：

```text
指令超时
  ↓
ref_cmd 无效
  ↓
PWM 输出清零
  ↓
PID 状态复位
  ↓
回到 CTRL_IDLE
```

然后再次进入阻塞等待状态。

总结一句话：

**ControlTask 在没有指令时是事件驱动，靠 `TaskNotify` 唤醒；收到有效指令后进入 `CTRL_RUN`，按 10 ms 周期运行 PID 闭环控制；如果指令超时或无效，再回到 `CTRL_IDLE` 阻塞等待。**

# 10、控制任务中两级模式的切换条件是什么？

控制任务的两级模式是：

```text
CTRL_IDLE  空闲/阻塞等待模式
CTRL_RUN   10ms周期闭环控制模式
```

切换条件可以这样理解：

```text
CTRL_IDLE
  ↓ 收到 CommTask 的 NOTIF_NEW_CMD，并且能读取到有效速度指令
CTRL_RUN
  ↓ 指令超时 / 指令无效 / 需要刹停并已进入安全停止状态
CTRL_IDLE
```

### 1. `CTRL_IDLE -> CTRL_RUN`

在 `CTRL_IDLE` 模式下，ControlTask 认为当前**没有有效运动指令**，所以会先做安全处理：

```text
PWM = 0
PID 状态复位
电机保持停止
```

然后阻塞等待新指令：

```c
xTaskNotifyWait(..., portMAX_DELAY);
```

当 CommTask 解析到有效速度帧后，会发送任务通知 `NOTIF_NEW_CMD`。ControlTask 被唤醒后，检查通知值，如果包含新指令标志，就读取最新速度命令：

```c
if (notify_val & NOTIF_NEW_CMD) {
    ref_cmd = Comm_GetLatestCmdVel();
    last_cmd_ms = now_ms();
    mode = CTRL_RUN;
}
```

所以 **从 IDLE 切到 RUN 的条件**是：

```text
收到 NOTIF_NEW_CMD 通知
并且读取到有效的 CmdVel 速度指令
```

文档第 1 页 3.5.1 和 3.5.2 里说明，空闲模式下 ControlTask 会用 `xTaskNotifyWait(..., portMAX_DELAY)` 阻塞等待，收到 CommTask 的新速度指令通知后，读取最新指令并切换到 `CTRL_RUN`。

### 2. `CTRL_RUN -> CTRL_IDLE`

进入 `CTRL_RUN` 后，ControlTask 按 **10ms 周期**运行闭环控制：

```text
读取/更新控制指令
↓
运动学逆解
↓
PID 计算 PWM
↓
输出到电机
↓
判断指令是否仍然有效
```

在运行过程中，它会持续检查有没有新命令。如果有新命令，就更新目标速度；如果长时间没有新命令，就认为上层控制失效或通信中断。

所以 **从 RUN 切回 IDLE 的条件**是：

```text
指令超时
或当前没有有效指令
或车辆已经完成刹停并处于稳定停止状态
```

通常逻辑是：

```c
if (now_ms() - last_cmd_ms > CMD_TIMEOUT_MS) {
    ref_cmd.valid = false;
    ref_cmd.vx_mmps = 0;
    ref_cmd.wz_mradps = 0;

    pwm_hw_apply(0, 0);
    pid_reset();

    mode = CTRL_IDLE;
}
```

更完整地说，RUN 模式下不是“没收到新命令就马上停”，而是：

```text
短时间没有新命令：继续使用上一条有效指令
超过超时时间：认为指令失效
指令失效后：目标速度置零，进入刹车/停机流程
停稳后：切回 CTRL_IDLE，重新阻塞等待新指令
```

### 3. 一句话总结

**`CTRL_IDLE -> CTRL_RUN` 的条件是收到 CommTask 的有效新速度指令；`CTRL_RUN -> CTRL_IDLE` 的条件是指令超时、指令无效或车辆已安全停稳。**

也就是：

```text
有有效指令：进入 RUN，10ms 周期闭环控制
无有效指令：回到 IDLE，PWM 清零，PID 复位，阻塞等待
```

# 11、收到目标速度后，控制任务中做了哪些步骤？

收到目标速度后，ControlTask 不是直接把目标速度写到电机，而是按 **“目标速度 → 运动学换算 → PID 闭环 → PWM 输出”** 的流程处理。

整体步骤是：

```text
收到目标速度 CmdVel
  ↓
读取最新速度指令
  ↓
判断指令是否有效/是否超时
  ↓
把底盘速度换算成各电机目标速度
  ↓
读取编码器反馈速度
  ↓
计算目标速度和实际速度的误差
  ↓
PID 计算控制量
  ↓
限幅、方向处理
  ↓
输出 PWM 给电机驱动
  ↓
10ms 后继续下一轮控制
```

### 1. 读取最新目标速度

CommTask 解析到有效帧后，会保存最新的速度指令。ControlTask 被通知后读取它：

```c
CmdVel_t cmd = Comm_GetLatestCmdVel();
```

这个指令里一般包含：

```c
vx_mmps;
vy_mmps;
wz_mradps;
```

也就是 X 方向速度、Y 方向速度和角速度。

### 2. 判断指令是否有效

ControlTask 会先判断这条速度指令还能不能用：

```text
cmd.valid 是否为 true
当前时间 - cmd.rx_tick 是否超过超时时间
```

如果指令超时，说明通信可能中断，系统不会继续执行旧速度，而是把目标速度置零，PWM 清零，并复位 PID。

### 3. 运动学解算目标轮速

如果目标速度有效，就把底盘速度换算成电机目标速度。

例如：

```text
底盘目标速度 vx / vy / wz
  ↓
运动学逆解
  ↓
各个轮子的目标速度 target_speed
```

如果是差速底盘，就是换算成左、右轮目标速度；如果是全向/麦轮底盘，就是换算成多个电机的目标速度。文档里的 ControlTask 流程展示的是收到速度指令后进入控制运行阶段，再根据目标速度执行后续 PID 调速。

### 4. 获取实际速度反馈

控制不是开环输出，而是要读取编码器反馈：

```text
编码器计数
  ↓
计算当前实际转速
  ↓
得到 actual_speed
```

实际速度用于和目标速度做比较。

### 5. PID 闭环计算

每个控制周期里，ControlTask 会计算：

```text
误差 = 目标速度 - 实际速度
```

然后送入 PID：

```c
pwm = PID_Update(&pid, target_speed, actual_speed);
```

PID 的作用就是让实际速度逐渐接近目标速度。上传文档第 2 页也展示了 PID 调速后的串口打印结果，能看到速度值逐渐接近目标速度。

### 6. PWM 限幅和方向处理

PID 输出后，不能直接无条件输出，还要做限幅：

```c
if (pwm > PWM_MAX) pwm = PWM_MAX;
if (pwm < -PWM_MAX) pwm = -PWM_MAX;
```

然后根据正负号决定电机方向：

```text
pwm > 0：正转
pwm < 0：反转
pwm = 0：停止
```

最后把绝对值作为 PWM 占空比输出给电机驱动。

### 7. 周期性重复执行

进入 `CTRL_RUN` 后，ControlTask 按固定周期运行，前面提到是 **10ms 一次，也就是 100Hz**：

```text
每 10ms：
读取/更新目标速度
计算轮速目标
读取编码器实际速度
PID 计算
输出 PWM
检查是否超时
```

所以一句话总结：

**收到目标速度后，ControlTask 会先判断指令有效性，再把底盘目标速度换算成各电机目标速度，读取编码器反馈，通过 PID 算出 PWM，最后输出到电机驱动；整个过程在 RUN 模式下按 10ms 周期循环执行。**
