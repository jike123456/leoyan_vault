# 7、解析到有效指令后，系统是如何处理的？

解析到有效指令后，系统不会在通信任务里直接控制电机，而是把指令**转换成业务数据、保存最新命令、再通知控制任务处理**。

整体流程是：

```text
CRC 校验通过
  ↓
进入 on_valid_frame()
  ↓
再次检查协议字段是否合法
  ↓
解析 payload
  ↓
生成 CmdVel_t 指令结构体
  ↓
保存为最新速度命令 s_latest
  ↓
通知 ControlTask 有新命令
  ↓
ControlTask 读取最新命令并执行控制逻辑
```

### 1. 先进入 `on_valid_frame()`

当前帧只有在状态机解析完整、CRC 校验通过后，才会进入：

```c
on_valid_frame();
```

但进入这个函数后，还不是马上执行控制，而是继续检查协议字段，比如版本号、消息类型、标志位、序列号、长度等。文档 3.4.5.1 里说明，有效帧处理的触发条件比较严格：完整接收一帧、CRC 通过、关键字段符合系统预期，才认为当前帧是有效帧。

典型代码逻辑是：

```c
static void on_valid_frame(void)
{
    if (s_ver    != PROTO_VER_EXPECT) return;
    if (s_msg_id != MSG_ID_CMD_VEL)   return;
    if (s_flags  != FLAGS_EXPECT)     return;
    if (s_seq    != SEQ_EXPECT)       return;
    if (s_len    != CMD_VEL_LEN)      return;

    ...
}
```

### 2. 解析 `payload`，生成速度指令

如果字段都合法，系统才会真正解析 payload。

对于 `CMD_VEL` 指令，payload 里包含 3 个 `int16_t` 类型的数据：

```text
vx_mmps   // x 轴速度，单位 mm/s
vy_mmps   // y 轴速度，单位 mm/s
wz_mradps // 角速度，单位 mrad/s
```

代码按小端格式解析：

```c
CmdVel_t v;

v.vx_mmps   = le_i16(&s_payload[0]);
v.vy_mmps   = le_i16(&s_payload[2]);
v.wz_mradps = le_i16(&s_payload[4]);
v.rx_tick   = xTaskGetTickCount();
v.valid     = true;
```

也就是说，通信层收到的原始字节会被转换成业务层可以直接使用的结构体 `CmdVel_t`。文档 3.4.5.2 中说明，这一步的本质是把“通信层的数据表示”转换成“业务层可以直接使用的参数”。

### 3. 保存为最新命令

解析完成后，系统会把这条指令保存到一个静态全局变量里，例如：

```c
static CmdVel_t s_latest = {0};
```

保存时要注意线程安全，因为通信任务和控制任务可能同时访问这块数据。文档中使用临界区保护：

```c
taskENTER_CRITICAL();
s_latest = v;
taskEXIT_CRITICAL();
```

这样可以避免 ControlTask 读取时，CommTask 正好写到一半，导致读到不完整或不一致的数据。文档 3.4.5.4 后面也强调，读取最新 `CmdVel_t` 时通过函数接口访问，并用临界区保护结构体拷贝。

### 4. 通知控制任务

保存完最新命令后，通信任务会通知控制任务：

```c
if (g_controlTaskHandle) {
    xTaskNotify(g_controlTaskHandle, NOTIF_NEW_CMD, eSetBits);
}
```

这里的意思是：**通信任务只负责接收、解析、校验和保存指令，不直接驱动电机；真正的控制逻辑交给 ControlTask。**

文档 3.4 的总体流程也说明，有效处理阶段会根据消息 ID 解析有效载荷，更新全局最新命令，并通过 FreeRTOS 任务通知机制通知 ControlTask 有新命令到来。

### 5. ControlTask 再读取并执行

ControlTask 收到通知后，会通过接口函数读取最新命令，例如：

```c
CmdVel_t Comm_GetLatestCmdVel(void)
{
    CmdVel_t out;

    taskENTER_CRITICAL();
    out = s_latest;
    taskEXIT_CRITICAL();

    return out;
}
```

然后 ControlTask 根据 `vx_mmps、vy_mmps、wz_mradps` 执行后续控制，比如运动学解算、速度目标更新、电机控制等。

所以可以总结为一句话：

**解析到有效指令后，CommTask 只把原始 payload 转成 `CmdVel_t`，保存为最新命令，并通知 ControlTask；ControlTask 再安全读取该命令并执行真正的运动控制。**

# 8、接7，不同的任务之间是如何通信的？什么机制？

接第 7 题，不同任务之间主要通过 **FreeRTOS 的任务通信机制** 来协作，不是直接互相调用控制逻辑。

在这个系统里，任务间通信可以分成三类：

```text
UART中断/DMA
  ↓
StreamBuffer
  ↓
CommTask
  ↓
共享最新命令 s_latest + 临界区保护
  ↓
TaskNotify 通知
  ↓
ControlTask
```

### 1. UART 接收中断/DMA → CommTask：用 `StreamBuffer`

串口底层接收数据后，不在中断里直接解析完整协议帧，而是把收到的字节放进 FreeRTOS 的 `StreamBuffer`。

典型逻辑是：

```c
xStreamBufferSendFromISR(
    g_rxStream,
    rx_buf,
    rx_len,
    &xHigherPriorityTaskWoken
);
```

然后 `CommTask` 从 `StreamBuffer` 里取数据：

```c
n = xStreamBufferReceive(
    g_rxStream,
    buf,
    sizeof(buf),
    portMAX_DELAY
);
```

这种机制适合传输**连续字节流**，因为 UART 收到的数据可能是半包、粘包或多帧连续数据。文档里的通信流程也是先由接收缓冲进入通信任务，再由通信任务逐字节喂给状态机解析。

### 2. CommTask 内部解析：状态机处理字节流

`CommTask` 拿到字节后，会逐字节调用解析函数：

```c
for (int i = 0; i < n; i++) {
    parser_feed_byte(buf[i]);
}
```

解析完成并通过 CRC 校验后，进入 `on_valid_frame()`。

所以 `StreamBuffer` 负责“搬运字节”，状态机负责“识别有效帧”。

### 3. CommTask → ControlTask：用共享结构体保存数据

解析到有效速度指令后，CommTask 会把 payload 转成业务结构体，例如：

```c
typedef struct {
    int16_t vx_mmps;
    int16_t vy_mmps;
    int16_t wz_mradps;
    TickType_t rx_tick;
    bool valid;
} CmdVel_t;
```

然后保存到全局最新命令：

```c
static CmdVel_t s_latest;
```

由于 `CommTask` 会写这个变量，`ControlTask` 会读这个变量，所以读写时需要临界区保护：

```c
taskENTER_CRITICAL();
s_latest = v;
taskEXIT_CRITICAL();
```

ControlTask 读取时也一样：

```c
CmdVel_t Comm_GetLatestCmdVel(void)
{
    CmdVel_t out;

    taskENTER_CRITICAL();
    out = s_latest;
    taskEXIT_CRITICAL();

    return out;
}
```

这里用的是**共享内存 + 临界区保护**。作用是避免一个任务正在写结构体，另一个任务同时读取，导致读到一半新数据、一半旧数据。文档中有效帧处理后会更新最新命令，并通过接口给控制任务读取。

### 4. CommTask → ControlTask：用 `TaskNotify` 通知有新命令

保存完最新命令后，CommTask 会通知 ControlTask：

```c
xTaskNotify(
    g_controlTaskHandle,
    NOTIF_NEW_CMD,
    eSetBits
);
```

ControlTask 里等待通知：

```c
uint32_t notify_value;

xTaskNotifyWait(
    0,
    0xFFFFFFFF,
    &notify_value,
    pdMS_TO_TICKS(10)
);

if (notify_value & NOTIF_NEW_CMD) {
    CmdVel_t cmd = Comm_GetLatestCmdVel();
    // 执行控制逻辑
}
```

这里用的是 FreeRTOS 的 **任务通知 Task Notification**。

它的作用类似轻量级信号量/事件标志位：  
CommTask 不直接控制电机，只是告诉 ControlTask：“有新的有效指令了。”

### 5. 为什么不用普通函数直接调用？

因为 CommTask 和 ControlTask 分工不同：

```text
CommTask：负责通信、收包、解析、校验
ControlTask：负责运动控制、电机控制、超时保护
```

如果 CommTask 直接调用电机控制函数，会让通信任务和控制任务耦合太强，也可能影响实时性。

现在这种方式的好处是：

```text
通信任务只管接收解析
控制任务只管控制执行
两个任务通过 FreeRTOS 机制解耦
```

总结一句话：

**不同任务之间主要通过 FreeRTOS 的 `StreamBuffer`、`TaskNotify` 和“共享变量 + 临界区保护”通信：StreamBuffer 传串口字节流，TaskNotify 传事件通知，共享结构体传最新控制指令。**
