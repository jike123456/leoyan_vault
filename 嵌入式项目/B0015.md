# 12、差速模型的输入输出是什么？怎么计算出来的？

差速模型这里做的是**运动学逆解**：把上层给的底盘目标速度，换算成左右轮各自应该达到的目标速度。

### 1. 输入是什么？

输入是上层控制指令里的两个量：

```c
vx_mmps    // 机器人前进方向线速度，单位 mm/s
wz_mradps  // 机器人绕自身中心旋转的角速度，单位 mrad/s
```

也就是：

```text
输入 = 底盘线速度 vx + 底盘角速度 wz
```

差速底盘没有横向平移能力，所以这里不使用 `vy_mmps`。文档 3.5.3 也说明，差速模型下上层运动指令主要包含 `vx_mmps` 和 `wz_mradps`，然后换算出左右轮目标速度。

### 2. 输出是什么？

输出是左右轮目标线速度：

```c
vL_ref   // 左轮目标速度，单位 mm/s
vR_ref   // 右轮目标速度，单位 mm/s
```

也就是：

```text
输出 = 左轮目标速度 vL_ref + 右轮目标速度 vR_ref
```

这两个速度后面会作为 PID 的目标值，和编码器反馈速度比较，再算 PWM 输出。

### 3. 怎么计算？

核心公式是：

```text
wz_rad = wz_mradps / 1000.0

half_base = WHEEL_BASE_MM / 2

vL_ref = vx_mmps - wz_rad * half_base
vR_ref = vx_mmps + wz_rad * half_base
```

代码形式就是：

```c
float wz_rad = (float)wz_mradps / 1000.0f;
float half_base = WHEEL_BASE_MM * 0.5f;

float vL = (float)vx_mmps - wz_rad * half_base;
float vR = (float)vx_mmps + wz_rad * half_base;

vL = clampf(vL, -MAX_WHEEL_SPEED_MMPS, MAX_WHEEL_SPEED_MMPS);
vR = clampf(vR, -MAX_WHEEL_SPEED_MMPS, MAX_WHEEL_SPEED_MMPS);

*vL_mmps = vL;
*vR_mmps = vR;
```

### 4. 为什么是这个公式？

差速车转弯时，左右轮走的圆弧半径不一样：

```text
左轮速度 = 车体中心速度 - 角速度 × 半轮距
右轮速度 = 车体中心速度 + 角速度 × 半轮距
```

因为机器人绕中心转动时，离旋转外侧更远的轮子速度要更快，内侧轮子速度要更慢。  
所以：

```text
wz > 0 时：左轮速度减小，右轮速度增大
wz = 0 时：左右轮速度相等，直线运动
vx = 0 且 wz != 0 时：左右轮一正一反，原地旋转
```

例如：

```text
vx = 100 mm/s
wz = 1000 mrad/s = 1 rad/s
WHEEL_BASE_MM = 200 mm
half_base = 100 mm
```

则：

```text
vL = 100 - 1 × 100 = 0 mm/s
vR = 100 + 1 × 100 = 200 mm/s
```

说明右轮比左轮快，车体向左/右发生转向，具体方向取决于坐标系定义。

一句话总结：

**差速模型输入是底盘的 `vx_mmps` 和 `wz_mradps`，输出是左右轮目标速度 `vL_ref`、`vR_ref`；计算方法是用线速度加减“角速度 × 半轮距”，得到左右轮各自的目标线速度。**

# 13、PID 输出如何映射到 PWM？

PID 输出映射到 PWM，本质上是把 **PID 算出来的有符号控制量** 转成电机驱动能识别的：

```text
方向信号 DIR + PWM 占空比
```

流程是：

```text
目标轮速 v_ref
  ↓
编码器反馈实际轮速 v_meas
  ↓
误差 error = v_ref - v_meas
  ↓
PID 计算输出 u
  ↓
u 限幅
  ↓
u 的正负决定方向
  ↓
|u| 映射成 PWM 占空比
  ↓
写入定时器 CCR
```

### 1. PID 先算出控制量

对左右轮分别做 PID：

```c
float err = target_speed - actual_speed;

float u = Kp * err
        + Ki * integral
        + Kd * derivative;
```

这里的 `u` 不是速度，而是控制输出量，可以理解成“电机应该加多大力”。

例如：

```text
u > 0：电机正转
u < 0：电机反转
u = 0：停止
```

文档里控制任务收到目标速度后，会进入周期控制流程，读取反馈速度并进行 PID 调速，最后输出到电机驱动。

### 2. 对 PID 输出做限幅

PID 算出来的值不能无限大，必须限制在 PWM 允许范围内：

```c
if (u > PWM_MAX) {
    u = PWM_MAX;
} else if (u < -PWM_MAX) {
    u = -PWM_MAX;
}
```

比如定时器 PWM 最大计数是 `1000`，那么输出范围就是：

```text
-1000 ~ +1000
```

### 3. 正负号决定电机方向

PID 输出 `u` 的正负用于控制方向引脚：

```c
if (u > 0) {
    motor_set_dir(FORWARD);
} else if (u < 0) {
    motor_set_dir(REVERSE);
} else {
    motor_stop();
}
```

也就是：

```text
u > 0  → 正转
u < 0  → 反转
u = 0  → 停止
```

### 4. 绝对值映射成 PWM 占空比

方向确定后，PWM 只使用 `u` 的绝对值：

```c
pwm = fabs(u);
```

如果 PWM 定时器的 ARR 是 `1000`，那么：

```text
pwm = 0      → 0% 占空比
pwm = 500    → 50% 占空比
pwm = 1000   → 100% 占空比
```

写入定时器比较寄存器：

```c
__HAL_TIM_SET_COMPARE(&htim, TIM_CHANNEL_x, pwm);
```

### 5. 如果 PID 输出是百分比，需要再换算

有些代码里 PID 输出不是 `0~ARR`，而是百分比，比如 `0~100`。  
这种情况下要换算成定时器比较值：

```c
uint16_t ccr = (uint16_t)(duty_percent * PWM_ARR / 100.0f);
```

例如：

```text
PID 输出 = 60
PWM_ARR = 1000

CCR = 60 × 1000 / 100 = 600
```

也就是 60% 占空比。

### 6. 实际代码通常会加死区补偿

电机在 PWM 太小时可能转不动，所以如果目标速度不是 0，但 PID 输出很小，可能会加一个最小启动 PWM：

```c
if (target_speed != 0 && pwm > 0 && pwm < PWM_MIN) {
    pwm = PWM_MIN;
}
```

例如：

```text
PWM_MIN = 120
PID 输出绝对值 = 50
实际输出 PWM = 120
```

这样可以克服电机静摩擦。

### 7. 举个例子

假设：

```text
PWM_MAX = 1000
PID 输出 u = -350
```

那么映射结果是：

```text
方向：反转
PWM：350
占空比：35%
```

如果：

```text
PID 输出 u = 1200
```

先限幅：

```text
u = 1000
```

映射结果：

```text
方向：正转
PWM：1000
占空比：100%
```

一句话总结：

**PID 输出先限幅，然后用正负号控制电机方向，用绝对值作为 PWM 占空比写入定时器；左右轮分别执行这一套映射，最终驱动两个电机达到目标速度。**

# 14、编码器反馈怎么读取，如何计算速度？

编码器反馈的读取和测速可以分成两步：**先用定时器输入捕获读脉冲，再把脉冲频率换算成轮速**。

### 1. 编码器反馈怎么读取？

编码器本质上输出的是一串脉冲：

```text
轮子转动 → 编码器输出脉冲 → MCU 定时器输入捕获 → 得到脉冲间隔
```

在这个项目里，为了先跑通闭环链路，文档中采用了**模拟编码器方案**：用 `TIM10 / TIM14` 输出 PWM，当作左右轮编码器脉冲，再把这个 PWM 信号接回 `TIM2` 的输入捕获引脚。后续如果换成真实编码器，只需要把真实编码器输出线接到输入捕获 IO，测速部分逻辑基本不用改。文档第 1 个扫描件第 1 页的 **3.6.2 编码器数据获取** 就说明了这个思路。

读取过程可以理解为：

```text
TIM2 输入捕获通道检测到一个脉冲边沿
  ↓
进入输入捕获中断
  ↓
读取当前捕获计数值 CCR
  ↓
和上一次捕获值相减
  ↓
得到两个脉冲之间的时间间隔 dt
```

典型代码逻辑是：

```c
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2) {
        uint32_t now = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_1);

        uint32_t diff;
        if (now >= last_capture) {
            diff = now - last_capture;
        } else {
            // 定时器溢出处理
            diff = (TIMER_PERIOD - last_capture) + now + 1;
        }

        last_capture = now;

        // diff 就是相邻两个编码器脉冲之间的计数差
    }
}
```

### 2. 如何计算脉冲频率？

定时器输入捕获得到的是 `diff`，也就是两个脉冲之间隔了多少个定时器计数。

如果定时器计数频率是 `timer_clk_hz`，那么：

```text
dt = diff / timer_clk_hz
hz = 1 / dt
```

合并后就是：

```c
float hz = (float)timer_clk_hz / diff;
```

其中：

```text
diff 越小 → 两个脉冲间隔越短 → 频率越高 → 轮子转得越快
diff 越大 → 两个脉冲间隔越长 → 频率越低 → 轮子转得越慢
```

### 3. 如何把频率换算成轮速？

文档里给出的核心公式是：

```text
v = hz × (circumference / PPR)
```

含义是：

```text
hz：每秒收到多少个编码器脉冲
PPR：编码器每转一圈输出多少个脉冲
circumference：轮子周长，单位 mm
```

所以：

```text
每个脉冲代表的距离 = 轮子周长 / 每圈脉冲数
轮速 = 每秒脉冲数 × 每个脉冲对应的距离
```

代码可以写成：

```c
float speed_mmps = hz * (WHEEL_CIRCUMFERENCE_MM / ENCODER_PPR);
```

### 4. 举例说明

假设：

```text
PPR = 500
轮子周长 = 628 mm
1 秒内收到 1000 个脉冲
```

那么：

```text
hz = 1000 Hz
轮子转速 = 1000 / 500 = 2 圈/s
线速度 = 2 × 628 = 1256 mm/s
```

也就是：

```text
v = 1000 × (628 / 500) = 1256 mm/s
```

### 5. 左右轮分别计算

差速车有左轮和右轮，所以一般会分别保存：

```c
float vL_meas;
float vR_meas;
```

左轮输入捕获算出 `vL_meas`，右轮输入捕获算出 `vR_meas`。  
然后 ControlTask 在 PID 控制时使用：

```text
左轮误差 = 左轮目标速度 vL_ref - 左轮反馈速度 vL_meas
右轮误差 = 右轮目标速度 vR_ref - 右轮反馈速度 vR_meas
```

再分别送入左右轮 PID，计算 PWM 输出。

一句话总结：

**编码器反馈是通过定时器输入捕获读取脉冲边沿，先计算相邻脉冲的时间间隔 `dt`，再得到频率 `hz = 1 / dt`，最后用 `v = hz × 轮子周长 / PPR` 换算成实际轮速 `mm/s`。**

# 15、代码中仿真电机模型的作用是什么？

代码中的**仿真电机模型**主要作用是：在没有真实电机、真实编码器的情况下，模拟“电机被 PWM 驱动后轮子会转起来，并产生编码器反馈”的过程，让整个闭环控制链路可以跑通。

可以理解成它在代码里临时替代了真实硬件：

```text
真实系统：
PWM输出 -> 电机转动 -> 编码器产生脉冲 -> MCU捕获脉冲 -> 计算轮速 -> PID反馈

仿真系统：
PWM输出 -> 仿真电机模型计算轮速 -> MCU输出模拟编码器脉冲 -> MCU捕获脉冲 -> 计算轮速 -> PID反馈
```

文档 3.6.2 里说明，为了降低对真实编码器硬件的依赖，项目设计了一套编码器轮速模拟方案：用 `TIM10 / TIM14` 输出 PWM 方波作为“模拟编码器脉冲”，再接回 `TIM2` 输入捕获口，从而在没有真实编码器时也能验证测速闭环。

### 1. 它的输入是什么？

仿真电机模型的输入一般是控制任务输出的 PWM，例如：

```text
left_pwm
right_pwm
```

也就是 PID 算出来后准备给左右电机的控制量。

### 2. 它的输出是什么？

输出是模拟出来的左右轮实际速度：

```text
vL_meas
vR_meas
```

也就是“如果这个 PWM 真正加到电机上，电机大概会转多快”。

### 3. 为什么不能直接把目标速度当反馈速度？

因为如果直接这样做：

```text
反馈速度 = 目标速度
```

那 PID 就没有真实调节意义了，误差永远很小，看不出控制效果。

仿真电机模型会模拟电机的响应过程，例如：

```text
PWM 变大
  ↓
轮速不是瞬间到目标值
  ↓
而是逐渐上升
```

这样 PID 才会经历：

```text
有误差 -> 输出 PWM -> 速度变化 -> 误差变小 -> PID 调节
```

更接近真实电机的闭环过程。

### 4. 它在闭环链路中的位置

完整流程可以写成：

```text
ControlTask
  ↓
目标速度 v_ref
  ↓
PID 计算 PWM
  ↓
仿真电机模型根据 PWM 算出模拟轮速
  ↓
根据模拟轮速生成模拟编码器脉冲频率
  ↓
TIM10 / TIM14 输出方波
  ↓
TIM2 输入捕获
  ↓
计算反馈速度 v_meas
  ↓
下一轮 PID 使用 v_meas
```

所以它不是单独为了“显示数据”，而是为了让 PID 有反馈输入。

### 5. 代码中大概是这样用的

可以理解成类似这种逻辑：

```c
void MotorSim_Update(float pwm_l, float pwm_r)
{
    // 根据 PWM 推算电机目标响应
    sim_vL += (pwm_l_to_speed(pwm_l) - sim_vL) * alpha;
    sim_vR += (pwm_r_to_speed(pwm_r) - sim_vR) * alpha;

    // 根据模拟轮速换算编码器频率
    float hz_l = sim_vL / (WHEEL_CIRCUMFERENCE_MM / ENCODER_PPR);
    float hz_r = sim_vR / (WHEEL_CIRCUMFERENCE_MM / ENCODER_PPR);

    // 用定时器输出对应频率的方波，模拟编码器脉冲
    EncoderSim_SetFreqLeft(hz_l);
    EncoderSim_SetFreqRight(hz_r);
}
```

这里的 `alpha` 表示电机响应速度，用来模拟电机不是瞬间达到目标转速，而是有惯性、有滞后。

### 6. 它的主要作用总结

仿真电机模型主要解决这几个问题：

```text
1. 没有真实电机时，也能测试控制任务
2. 没有真实编码器时，也能测试编码器测速
3. 可以验证 PID 调速链路是否正确
4. 可以验证目标速度 -> PWM -> 反馈速度的闭环逻辑
5. 后续接入真实电机/编码器时，替换成本低
```

一句话总结：

**仿真电机模型的作用是用软件模拟真实电机对 PWM 的速度响应，并进一步生成模拟编码器反馈，让系统在没有真实电机和编码器时，也能跑通“PID 输出 PWM → 轮速变化 → 编码器反馈 → PID 再调节”的完整闭环。**
